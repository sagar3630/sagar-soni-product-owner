How I work

I started as a trainee business analyst writing BRDs, and moved into product ownership because I wanted to own the decisions, not just document them.

Today I run several client products at once at DianApps, with a cross-functional team of 15+. I lean on data before opinions, write stories developers don't have to guess at, and use AI tools like Claude Code to take the busywork out of refinement.

Data before the PRD

I read the requests, orders or games first, find where the core loop breaks, and only then write the brief.

Edge cases are acceptance criteria

Exceptions go into the story, not into a bug ticket after release, so QA and developers share one definition of done.

One source for every number

Each metric has a single owner and source, so the founder, finance and the dashboard always agree.
